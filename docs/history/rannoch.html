Why leave the agent feature

  • Preview limits worked around one by one: no file-path tool inputs, a failing tool kills the agent, JSON mangled in structured answers, an agent hung for an hour.
  • The multi-agent logic already lived outside Nextflow: the lab's designer, engineer and reviewer rounds are a bash loop.
  • The agent sandbox has to carry Java, the scheduler client and the JDK's links into /etc.
  • A legion needs control the dataflow model handles badly: agents starting agents, memory across steps, turn and cost budgets.

What stays

  • The plan check, the run-time check against the approved plan, the report check.
  • The skills, the pipeline registry, the reference catalogue.
  • The sandbox for agent-written code, and the agent sandbox.
  • The benchmarks and scorers, so every step is measured against Geth 1.x.
Steps

Measured before it replaces anything

  1. R1

    The harness, and the planner on it

    done

    The planner ported with the same instructions, tools and skills, so only the harness differs. GETH_PLANNER=harness geth plan … runs it, sandboxed. Smoke test on the yeast RNA-seq delivery: 13/13 in 1 minute, 5 model calls, 27 MB of memory.

  2. R2

    Head-to-head planner benchmark

    running

    15 test deliveries, 3 plans each, for each planner: 90 plans scored against the known design. Compared on correctness, time, memory, model use and failures. Your call on R3 comes after these numbers.

  3. R3

    A planner that asks you

    next, if R2 holds up
    • First what the data cannot tell (kit, strandedness, design, organism), then the pipeline options that change results for your project. Everything else keeps its default, and the plan says why for each option it sets.
    • A conversation in your terminal, a few questions at a time, each with a recommended answer. Detached runs and benchmarks answer from a file.
    • The pipeline's own parameter schema becomes a tool, so the planner can find the options that matter. The result is a complete command line.
    • Scored with a simulated user who knows each test delivery's facts.
  4. R4

    The other agents move over

    proposed

    Operator, reporter and the lab's designer, engineer and reviewer on the harness, each against its own benchmark. Nextflow then only runs pipelines.

  5. R5

    The legion

    proposed

    A coordinator agent that works out what the data needs and starts specialists as it goes: planner, engineer, reviewer. Geth's checks decide at every step. Budgets live in the harness, which also makes the paid frontier-model comparison easy to cap.

Decisions

Decision log

  • 2026-10-21Simplify: run the agents on Geth's own harness, keep Nextflow for pipelines. Start with a measured trial of the planner.
  • 2026-10-21Codename Rannoch. Geth 2.0 lives in the Geth repository on feature/rannoch; Geth 1.x stays on master until 2.0 beats it.
  • 2026-10-21If the trial holds up, the planner asks questions: interactive in the terminal, with an answers file for detached runs and benchmarks. First what the data cannot tell, then the options that matter.
