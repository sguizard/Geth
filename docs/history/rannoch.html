Geth 2.0 · codename

Rannoch

Geth 2.1.0 released

Geth on its own ground. The agents moved from Nextflow's preview agent feature to Geth's own small harness, which talks to the model service directly; since Geth 2.0 it is the only one. Nextflow keeps doing what it is best at: running the pipelines and the tools' jobs. The goal is a legion of agents that takes raw data to curated results, asking you what the data cannot tell.

The move

Same checks, a lighter way to run the agents

Why leave the agent feature

  • Preview limits worked around one by one: no file-path tool inputs, a failing tool kills the agent, JSON mangled in structured answers, an agent hung for an hour.
  • The multi-agent logic already lived outside Nextflow: the lab's designer, engineer and reviewer rounds are a bash loop.
  • The agent sandbox has to carry Java, the scheduler client and the JDK's links into /etc.
  • A legion needs control the dataflow model handles badly: agents starting agents, memory across steps, turn and cost budgets.

What stays

  • The plan check, the run-time check against the approved plan, the report check.
  • The skills, the pipeline registry, the reference catalogue.
  • The sandbox for agent-written code, and the agent sandbox.
  • The benchmarks and scorers, so every step is measured against Geth 1.x.
Steps

Measured before it replaces anything

  1. R1

    The harness, and the planner on it

    done

    The planner ported with the same instructions, tools and skills, so only the harness differs. GETH_PLANNER=harness geth plan … runs it, sandboxed. Smoke test on the yeast RNA-seq delivery: 13/13 in 1 minute, 5 model calls, 27 MB of memory.

  2. R2

    Head-to-head planner benchmark

    done

    15 test deliveries, 3 plans each, for each planner: 90 plans scored against the known design. The harness planner was correct on all 45 and three times faster, with a fifteenth of the memory. It also exposed a sandbox bug in Geth 1.x: shared databases were not visible to the agents (fixed in v1.9.3).

  3. R3

    A planner that asks you

    done
    • ASK_USER: in your terminal, a few questions at a time, each with options and a recommended answer that Enter takes. With geth plan … --answers file, a stand-in answers from what the file says. At most 2 rounds of 5 questions. The questions and answers are kept with the plan, and geth show prints them.
    • PIPELINE_OPTIONS: the pinned release's parameter schema, by section or by word, so the planner finds the options that matter. geth show now prints the full command line Geth will run.
    • When the check refuses the same plan three times, the planner is told to ask you rather than resubmit; it stops at six.
    • Every pipeline skill lists what to ask when the delivery does not say, and INSPECT_READS measures read lengths instead of guessing them.
    • Result: on sparse deliveries 15/18 plans fully correct with questions against 3/18 without; on held-out deliveries 8/9 against 6/9. With full READMEs it asks nothing (median) and stays at 18/18. Try it with GETH_PLANNER=harness geth plan ….
  4. R4

    The other agents move over

    done
    • GETH_RUNNER=harness: the operator and reporter (geth run, geth report), and the single-cell analyst. GETH_LAB_RUNNER=harness: the lab's designer, judge, engineers and reviewers. Same instructions, tools and skills as the Nextflow agents.
    • Two new checks the typed answers could not give. Geth refuses an outcome the pipeline's log contradicts, either way. A report with numbers it cannot trace goes back to the reporter once, to correct, before it is saved.
    • The tools' scheduler jobs (single-cell toolbox, lab tests) go through two small Nextflow job files with your site's config. Nextflow now only runs jobs.
    • The operator runs the approved plan by naming the pipeline, instead of copying the plan out again. A run takes one driver slot instead of two.
    • Result: every agent works on Rannoch, as well as or better than on Nextflow's agents. The checks are stricter: reports trace every number, and outcomes match the logs. Try it with GETH_RUNNER=harness geth run ….
  5. R5

    The legion: projects

    released
    • geth legion new / approve / run: a coordinator agent turns a question into steps. A step is a pipeline, a follow-up, an Ensembl genome download, a gap, or (with --lab) the lab. Each pipeline step is an ordinary run: you approve its plan as before.
    • The coordinator plans, reviews each finished step (continue, stop, or propose new steps for you to approve) and writes the project report, number-checked against every step. It never runs anything itself, and --overrule lets you go on when it stops.
    • Gaps are named, never improvised: the nf-core catalogue (145 pipelines) tells which one would do it, e.g. nf-core/smrnaseq for microRNAs.
    • --model and --budget for the lab, so you can try Sol there with a hard cap: a request that would cross the budget is not sent.

Where the time goes: in the Nextflow version, the agent's own work took 1.6 minutes per plan (median). The feature then asked the model to write the whole plan again as a typed record, which took 4.2 minutes, two thirds of the planning. The harness takes the plan from the agent's last tool call instead, written once. Nextflow itself added only seconds. Every delivery was faster with the harness, from 1.6 times (multiplexed 10x) to 5.7 times (index reuse).

The Nextflow reporter is quicker because it writes once and saves what it wrote. Rannoch sent 11 of 31 first drafts back (one to five numbers each, such as read totals rounded to "182,000"), and every one came back clean. The only number left flagged on an operator run was a bound (">93% mapped"), which the check cannot verify. Agent time is almost all the model's: a median of 109 seconds of model calls per run. The rest is Geth's checks and the pipeline's launch.

Found on the way, and fixed:

  • chipseq and atacseq reports had no QC table and no peak counts, because MultiQC wrote only JSON there.
  • mag's newer MultiQC crashed the results summary.
  • The single-cell analyst's revisions had always been refused on format (also in Geth 1.x). Revisions that name only the changed keys, or list values, now work.
  • A refused revision made my first outcome check reject the analyst's true claim.

Decisions

Decision log

  • 2026-10-21Simplify: run the agents on Geth's own harness, keep Nextflow for pipelines. Start with a measured trial of the planner.
  • 2026-10-21Codename Rannoch. Geth 2.0 lives in the Geth repository on feature/rannoch; Geth 1.x stays on master until 2.0 beats it.
  • 2026-10-21If the trial holds up, the planner asks questions: interactive in the terminal, with an answers file for detached runs and benchmarks. First what the data cannot tell, then the options that matter.
  • 2026-10-21Trial passed: 45/45 correct against 43/45, three times faster, a fifteenth of the memory. On to R3. The sandbox fix it uncovered goes to Geth 1.x as v1.9.3.
  • 2026-10-21R3 approved, with the two additions: stop resubmitting a refused plan and ask instead; browse the pipeline's options through its schema.
  • 2026-10-22R3 done: asking lifts sparse deliveries from 3/18 to 15/18 fully correct, and costs nothing when the README is complete. Next is your call: R4 (the other agents) or trying the planner on your own data first.
  • 2026-10-22Your first real use (chicken OCM): the planner recommended an impossible chemistry and overrode your answer silently. Fixed: recommendations must agree with the files, overrides are explained, contradicting answers are flagged, and progress lines show what it is doing.
  • 2026-10-22The reads now check the plan: amplicon primers, 10x barcode read length, read length, RRBS motif. On past plans they flag only real errors.
  • 2026-10-22Comparison through ELM (your runs, hard budgets): Sol 26/27 sparse and fastest for $2 per 45 plans; Luna 23/27 for $0.35; Qwen 19/27, free. The comparison also exposed two plan-check gaps, now closed.
  • 2026-10-22Estimate for a frontier comparison with GPT-6 Astra (third-party prices, $10 / $50 per million tokens): about $60 for the R3 benchmark without caching, $30–35 with it, a $10–15 pilot first. Only with you, with a hard budget cap in the harness.
  • 2026-10-22Qwen stays the free default planner; Sol can be switched on for one plan with geth plan … --model sol, within a 50-cent cap. You start paid plans, never Geth on its own.
  • 2026-10-23ELM's own prices are unknown, so the cost estimates keep OpenAI's list prices.
  • 2026-10-23R4 started: the planner is good enough to generalise the harness to the other agents.
  • 2026-10-23R4 done: operator, reporter, analyst and lab agents run on Rannoch. 8/8 runs honest, 31/31 reports fully traced, both lab builds delivered. Geth no longer needs Nextflow's agent feature; Nextflow only runs the pipelines and jobs.
  • 2026-10-23Rannoch becomes the only Geth: the Nextflow agents are removed ("dead weight now"), released as Geth 2.0.0 on master. Runs planned with 1.x still run and report.
  • 2026-10-23R5 (projects): you approve every step's plan; gaps are reported, the lab only with --lab; command geth project (renamed geth legion at release). Sol for the lab: you run it, with a hard budget per command.
  • 2026-10-25Sol in the lab, your runs: a 19/20 design for $0.05 and a careful build for $0.44, held back by its own strict reviewer. 2.1.1 fixed geth legion run --detach.
  • 2026-10-25Released as Geth 2.1.0. You renamed the command geth legion: "You deserve the honours after all."
